# TDM Skill 網站能力優化分析報告

> 分析日期：2026-07-12  
> 分析範圍：`.claude/skills/tdm`、`app/tdm_web.py`、TDM 公開網站與 API  
> 性質：唯讀分析報告，不包含程式碼修改

## 一、結論摘要

目前 TDM skill 已具備完整的基本閉環：新聞查詢、全文搜尋、影片下載、裁剪、SQLite、Telegram/WebDAV 推送、Web UI 與遠端 CLI。架構亦已有 `tdm_core.py`、`tdm_tool.py`、`tdm_remote.py`、`push_manager.py` 的基本分層。

現階段最值得投入的方向分為兩類：

1. **先修正既有可靠性問題**：搜尋分頁、本地/遠端契約、節目 URL、推送 metadata、yt-dlp 進度、`.env` 載入及自動化測試。
2. **再擴充 TDM 網站內容能力**：節目重溫、電台音訊、圖片新聞、直播、節目表、多語言及完整搜尋類型。

優先推薦加入的是「節目 slug + 重溫片段」「音訊/圖片媒體模型」「直播及節目表」「多語言」。字幕、直播錄製、專題 CLI 與短視頻詳情暫不宜承諾。

## 三、既有功能的主要問題

## 3.1 P0：應優先修正

### 1. 搜尋沒有真正分頁

`query_search()` 固定請求搜尋 API 第 1 頁，Web 收到 `page` 後也未傳入核心。因此搜尋第 2 頁可能仍顯示第 1 頁結果。

影響：

- Web 搜尋分頁失真。
- 遠端 CLI 沒有搜尋 page 契約。
- `total` 有時代表上游總數，有時只是當次過濾結果數。

建議：

- 將搜尋獨立為 `/api/search`。
- 核心接受 `page`、`size`、`type`、`lang`。
- 保留上游 `count` 為 total。
- 不應在全文搜尋中靜默忽略 category/date。

### 2. 本地與遠端搜尋語義不同

本地 `news --search` 是「當頁新聞客戶端過濾」；遠端相同命令則轉成 TDM 全文搜尋。

建議：

- `news` 僅負責新聞列表。
- `search` 僅負責全文搜尋。
- `news --search` 保留一段兼容期並提示改用 `search`。

### 3. 文件宣稱節目 URL 可下載，但核心固定查新聞詳情

現有下載器從 URL 抽取數字後固定請求 `/api/v1.0/news/{id}`。現行 TDM 節目頁已改以 slug 為主要識別，舊式 numeric program URL/endpoint 不可靠。

建議：

- 不再把所有 TDM URL 視為新聞 ID。
- 新增 resource resolver，區分 news、program、short-video。
- 節目使用 `{slug}/details` 和 `{slug}/review`。

### 4. 手動 WebDAV 推送可能覆寫影片 metadata

Web 手動推送成功後再次呼叫 `record_video()`，可能清空既有 `news_id`、裁剪時間、來源影片及 `source_type`。

建議：

- 手動推送只更新 push 狀態。
- 不應重新建立或覆寫影片內容 metadata。
- 推送結果最好獨立記錄 channel、status、remote URL、error。

### 5. 不存在的媒體檔可能被誤當純文字推送

目前核心以「檔案是否存在」判斷文字或媒體；指定不存在的影片路徑時，可能把 caption 當成 Telegram 文字送出。

建議：

- 明確分開 `push_text` 與 `push_media`。
- 媒體路徑不存在直接失敗。

### 6. yt-dlp 進度與模組偵測問題

- `_run_ytdlp()` 可能向 CLI 回傳浮點百分比，但 CLI 使用整數格式及字串乘法。
- `python -m yt_dlp` 的偵測命令組裝不正確。

這些問題可能令 yt-dlp 路徑失敗後靜默回退 ffmpeg，降低速度且不易察覺。

### 7. Web `.env` 載入順序過晚

`app/tdm_web.py` 在載入 project `.env` 前已 import `tdm_core`，導致下載目錄、DB、WebDAV、Telegram 等 import-time 設定可能已被凍結。

建議：先載入環境設定，再 import core；明確規則為：

```text
系統環境變數 > project .env > skill .env > 預設值
```

### 8. 缺少可重跑自動化測試

目前有人工測試報告與 verify recipe，但沒有 pytest/unittest、fixtures 或 CI。既有 PASS 無法在每次改動後自動重現。

最少應覆蓋：

- 搜尋 page 1/page 2。
- local/remote 契約一致。
- program slug。
- WebDAV metadata 不被覆寫。
- yt-dlp 浮點進度。
- 不存在媒體推送。
- `.env` 載入時序。
- db-sync 非法參數。

## 3.2 P1：可靠性與安全

### 1. `db sync --all-days` 語義不成立

已知 TDM 的 `IsShowSevenDay` 行為不能用來取得完整歷史資料；現有 `--all-days` 可能反而回傳更少資料。

建議：先停用或明確拒絕此選項；歷史資料應設計獨立日期範圍同步流程。

### 2. `/api/db-sync` 驗證不足

未完整驗證 JSON object、布林與 pages 上限，可能出現 500 或過量上游請求。可直接重用現有 Web 驗證 helper。

### 3. 背景下載任務無治理

目前下載任務：

- 無併發上限。
- 無 queue 上限。
- 無取消。
- 無完成後 TTL 清理。
- server restart 後遺失狀態。

適合在後續獨立加入 task registry，不宜與內容功能一次混改。

### 4. 任意 URL 下載存在 SSRF 面

Web Server 可將 URL 交給 yt-dlp/ffmpeg。若部署在公開或不可信網路，需拒絕 localhost、私網、link-local、非 HTTP(S) 與內嵌帳密；遠端模式建議預設只接受 TDM 及其媒體 CDN。

### 5. Web 認證只適合可信內網

目前屬輕量密碼保護，缺少登入速率限制、正式 session、Secure Cookie、CSRF 等公網防護。部署到公網前需另外加固。

## 四、TDM 網站可擴充能力

## 4.1 P0：節目詳情與重溫

現行節目以 slug 為主，例如：

```text
/api/v1.0/program/{slug}/details
/api/v1.0/program/{slug}/review
```

已確認可取得：

- 節目名稱、封面、介紹。
- 頻道、主持人、播放說明。
- 歷史集數與日期。
- 集數內多個片段。
- 影片 `video` 或電台音訊 `radio` m3u8。
- `shareUrl`。
- 地區/重溫限制欄位。

建議新增：

```text
program show <slug>
program review <slug> --page N --limit N
```

價值：高。可直接補上目前文件宣稱但實際未完整支援的節目能力。

## 4.2 P0：音訊與多圖新聞

新聞詳情不只包含 `video`，亦可能包含：

- `audio`
- `images[]`
- `cover`
- `iconIndicator.isAudio`
- `iconIndicator.isImage`
- `iconIndicator.isVideo`

建議將資料模型由「是否有影片」提升為：

```text
video | audio | images | mixed | text
```

可新增：

- 新聞音訊下載。
- 圖片首圖/全部圖片下載。
- mixed media 的正確展示。

## 4.3 P0：直播頻道

已確認：

```text
GET /api/v1.0/live/categories
```

可取得：

- 電視與電台頻道。
- 頻道 ID、名稱、logo、slug。
- `onlineFeed` 直播串流。
- `liveProgramName` 當前節目。

建議先提供唯讀命令：

```text
live --type tv|radio
```

本輪不建議加入錄製；錄製涉及長任務、停止條件、空間及任務治理。

## 4.4 P0：電視/電台節目表

已確認端點：

```text
/api/v1.0/program-list/Channel?type=tv|radio
/api/v1.0/program-list/categories
/api/v1.0/program-list/{date}?date=YYYY-MM-DD&type=tv|radio&channelId=ID
```

可取得：

- 可查日期。
- 電視/電台頻道。
- 每個節目的開始時間。
- 節目 slug、episode ID、是否直播/重溫/新聞。
- 頻道直播 feed。

建議新增：

```text
schedule channels --type tv|radio
schedule categories
schedule --date YYYY-MM-DD --type tv|radio --channel-id ID
```

## 4.5 P1：完整搜尋類型

TDM 搜尋已確認四類：

- `search_news`
- `search_short_video`
- `search_program`
- `search_pressrelease`

目前 CLI 缺少 `search_pressrelease`，並將所有結果 URL 固定輸出成新聞詳情 URL。

建議每個搜尋結果回傳：

- `source_type`
- `id`
- `slug`
- `detail_url`
- `media_types`
- `downloadable`

短視頻應直接使用搜尋/列表回傳的 media URL，不假設存在 detail endpoint。

## 4.6 P1：多語言

新聞列表已確認接受：

- `zh-hant`
- `zh`
- `pt`
- `en`

建議為 news/search/program/live/schedule 統一加入 `--lang`。搜尋端是否能嚴格限制語言仍需持續驗證，不應過度承諾。

## 4.7 P1：影片庫 CLI

Web API 已有影片列表、分組、版本、單筆查詢、下載檔案、刪除及手動推送能力，但遠端 CLI 尚未暴露。

低成本可新增：

```text
videos list --grouped
videos show --id ID
videos versions --news-id ID
videos fetch --id ID
videos delete --id ID
videos push --id ID --target webdav|tg
```

## 4.8 P2：專題

已確認：

```text
/api/v1.0/special
/api/v1.0/special/{slug}
/api/v1.0/special/{slug}/news
/api/v1.0/special/{slug}/related-program
/api/v1.0/special/{slug}/program-review
```

專題具新聞、tag、相關節目及重溫等資料，但會引入新的集合模型。建議先記錄 API，待統一媒體模型穩定後再加入 CLI。

## 五、暫不建議加入

### 1. 字幕下載

抽樣的新聞、節目資料及 HLS manifest 未發現獨立字幕欄位或 `EXT-X-MEDIA:TYPE=SUBTITLES`。不能由此斷言全站永遠沒有字幕，但目前證據不足，不應宣稱支援。

### 2. 短視頻獨立詳情

短視頻 category/list/search 已確認，但獨立 detail endpoint 未確認。應使用列表/搜尋直接提供的媒體 URL。

### 3. 直播錄製與定時錄影

需先完成背景任務併發、取消、TTL、空間配額與恢復機制。

### 4. 公網級認證

屬另一個安全與部署專案，不宜與內容能力混成一次改動。

## 六、推薦實施順序

### 第一階段：可靠性修正

1. 建立離線 pytest 與 API fixtures。
2. 修正搜尋分頁及 local/remote 契約。
3. 修正 yt-dlp、媒體推送、`.env` 載入。
4. 修正 WebDAV metadata 與 channel-specific 推送記錄。
5. 停用不可靠的 `--all-days` 語義。

### 第二階段：高價值網站內容

1. 建立 normalized content/media 模型。
2. 加入 program slug details/review。
3. 加入 audio/images/mixed。
4. 加入四類搜尋與正確 URL。
5. 加入 `--lang`。
6. 加入 live/schedule 唯讀能力。

### 第三階段：治理與進階能力

1. 影片庫 CLI/remote 能力。
2. URL allowlist 與 SSRF 防護。
3. 背景任務 queue、併發、取消、TTL。
4. 專題功能。
5. 公網部署安全。

## 七、驗收建議

### 離線自動化

- Mock TDM API：精確驗證 URL、Page、PageSize、Lang、SelectType。
- Core：新聞/節目/搜尋 normalization。
- CLI：argparse、exit code、輸出 schema。
- Remote：HTTP method、path、query/body。
- Flask：輸入驗證、HTTP status、推送 metadata、影片庫 CRUD。
- SQLite：舊 DB additive migration，不刪既有資料。

### 少量 Live Smoke

每次發布只做唯讀、小量請求：

1. 新聞列表 1 頁。
2. 一個新聞詳情。
3. 四類搜尋各一筆。
4. 一個 program slug details/review。
5. live categories。
6. 單一頻道當日 schedule。

不在 smoke 中下載完整媒體，不推送 Telegram/WebDAV，不大量翻頁。

## 八、風險清單

| 風險 | 影響 | 建議 |
|---|---|---|
| TDM API 未公開版本承諾 | 欄位或 URL 漂移 | fixtures + live smoke + capability fallback |
| 節目 slug、集數 ID、片段 ID 層級不同 | 下載錯資源 | 建立 typed resource model |
| `playelist.m3u8` 拼字不標準但屬官方實際 URL | 自行修正可能破壞播放 | 只修正精確 `/play` endpoint |
| 搜尋語言控制未完全確認 | 結果可能跨語言 | 文件標為已知限制 |
| 節目有地區/期限限制 | URL 存在但不可播放 | 顯示限制欄位，不保證可播 |
| 任意 URL 遠端下載 | SSRF | 遠端 allowlist + IP 驗證 |
| 背景任務無界 | 資源耗盡 | queue/limit/TTL/cancel |
| 推送 metadata 混用 | 影片版本資料損壞 | channel-specific push record |

---

## 九、最終建議

若只選一個「功能擴充包」，推薦：

> **節目重溫 + 音訊/圖片混合媒體 + 多語言 + 直播/節目表唯讀查詢**

但在擴充前，應先完成搜尋契約、推送 metadata、yt-dlp、`.env` 與測試基線修正。這樣可避免把現有資料一致性及遠端契約問題帶入更多新功能。
